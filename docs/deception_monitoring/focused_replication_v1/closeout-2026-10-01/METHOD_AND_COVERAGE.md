# What this study can conclude

Status: method and coverage review on 1 October 2026. The core roleplay/control analysis is complete and has been independently rechecked locally. The [results report](REPORT.md) describes a detectable signal, limited detection at the frozen threshold, and a stronger observed text comparator. The seven additional evaluation settings are not yet complete.

## The question

Can a linear direction learned from instructions to be honest or dishonest distinguish actual honest and deceptive responses in the authors' roleplay scenarios when used on a much smaller Llama model?

The training responses are identical true facts under different instructions. They are not examples of actual lying. Transfer from those instructions to newly generated behavior is the interesting test. Successful separation on training tokens alone would not answer it.

This is a smaller-model adaptation of Goldowsky-Dill et al., [Detecting Strategic Deception Using Linear Probes, arXiv:2502.03407v1](https://arxiv.org/html/2502.03407v1), using [their pinned implementation](https://github.com/ApolloResearch/deception-detection/tree/f8ec4010e74927394709dffa22b97bdf8cd5a62f). It is not a new invention of linear deception probes or a reproduction of every experiment in the paper.

## What matches and what differs

| Component | Executed or frozen method | Important qualification |
| --- | --- | --- |
| Training data | The original 306 true facts, 612 paired honest/dishonest conditions, source order, first 490 conditions for fitting and final 122 held out | All conditions remain accounted for. The source's five-space-separated-word exclusion leaves some empty masks. Those are retained, not repaired into longer training examples. |
| Probe | Train-only standardization; token-level logistic regression, L2, `C=0.1`, no intercept, seed 42; raw linear scores | No response pooling before fitting, PCA, neural monitor, or class-balancing substitution. The local implementation has direct upstream estimator/scorer parity on the same states, not numerical parity with the original 70B experiment. |
| Readout | One separately fitted probe at each of hidden-state tuple indices 1..28; fixed primary index 22, secondary 8 | Index 0 is the embedding state and is excluded; index 28 is after the final normalization, matching the upstream tuple convention. Layer 22 of 28 is much later in relative depth than layer 22 of 80. Layer 8 is a prespecified relative-depth sensitivity, not a layer selected because it performed best. The full profile is descriptive. |
| Evaluation | All 371 original roleplay scenarios, one saved on-policy 3B continuation each | The original YAML's example responses and expected labels are not substituted for generated responses and observed grades. |
| Generation | Frozen Llama-3.2-3B-Instruct revision, Colab T4 FP16, full context, temperature 1 and 3,072-token ceiling | This is not the paper's Llama-3.3-70B-Instruct or its Together backend. Local sampling defaults are disclosed rather than described as recovered provider defaults. |
| Token scoring | Source-normalized response text, population-specific masks, raw token-score mean | Chat template, whitespace, adjacent messages, and 2026 date parsing require compatibility checks. Activation collection is not finished evidence until those checks pass. |
| Memory adaptation | Batch-one FP16 capture, 128-token chunks with the KV cache retaining full prior context, all registered masked positions and layers saved | A chunk is not a context truncation or a reduction to response-level means. | Prior exposure | All source rows retained; the 96 previously generated scenarios are tagged and the other 275 reported separately; a stricter 268-scenario stratum excludes all documented prior exposure | These strata contain 225 and 219 binary cases respectively. Even the stricter stratum is not an untouched confirmation: all 371 saved outputs predate the focused amendment. Multiple outputs, paired instructions, and overlapping history variants require grouping when estimating uncertainty. Nothing in this table treats saved 70B reports as fresh 3B behavior.

It begins with an authored fixed history, generates the trade decision, grades whether it used insider information, generates a report on the eligible yes/ambiguous branch, and asks the follow-up only for implied/concealed reports. Its released 6,000 trajectories combine two logged runs; `run_eval` itself defaults to 100 repetitions. The absent logs and original provider defaults must not be filled in from that default as if they specified the published run. The bounded local helper now matches the pinned generator on 57 new offline tests. This removes a software gap without claiming any new empirical trajectory.

The source AI-audit setting itself has an interpretation limit: factual inconsistency need not establish intentional deception. Source-matching labels do not remove that limit. ## Interpretation rule

A useful conclusion must distinguish three things: separating honest from deceptive roleplay responses, detecting deceptive responses at the ordinary-chat threshold, and unnecessarily flagging honest responses in deceptive contexts. A strong AUROC alone does not guarantee a useful low-false-alarm monitor.

If the primary readout is weak while another layer is strong, report the fixed primary result and the full profile. A descriptive winning layer is a hypothesis for a fresh study, not a retroactive primary success. If labels, token masks, or archive identities fail, report a validity problem rather than presenting their metrics as scientific evidence.

Even a positive result would establish detection on this adapted task, not prevented deception, general hallucination detection, reward-hacking detection, a causal mechanism, online safety, or deployment robustness. The report should be valuable because its findings are auditable, not because its conclusion is necessarily favorable.
